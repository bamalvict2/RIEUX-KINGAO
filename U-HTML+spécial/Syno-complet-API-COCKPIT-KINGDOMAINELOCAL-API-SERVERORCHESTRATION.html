KING-AO – Pipeline opérationnel
Mode Cockpit
🟩 1 — Point d’entrée
PORTAL Interface web utilisateur

L’utilisateur clique, le PORTAL ne fait que déclencher l’adaptateur.

  • aucune logique métier
  • ne parle pas aux modules
  • appelle portal-orchestrator.sh
👉 PORTAL
🟦 2 — Adaptateur
portal-orchestrator.sh Traducteur PORTAL → Cockpit

Reçoit l’action utilisateur et prépare le contexte d’exécution.

  • vérifie mode / action / paramètres
  • prépare les variables d’environnement
  • appelle STYLE-ORCH-KING-AO.sh
👉 portal-orchestrator
🟩 3 — Cockpit humain
STYLE-ORCH-KING-AO.sh Interface opérateur

Menus, couleurs, confirmations, navigation opérateur.

  • affiche les menus
  • demande les confirmations
  • prépare les commandes finales
  • appelle orchestrator.sh
👉 STYLE-ORCH
🟦 4 — Cerveau technique
orchestrator.sh Chef d’orchestre

Aucune UI, uniquement exécution technique et gestion des erreurs.

  • lit les configs KING-AO
  • charge les modules
  • lance les actions techniques
  • gère les erreurs et renvoie les résultats
👉 orchestrator.sh
🟩 5 — Modules techniques
Modules KING-AO METIER / KINGDOMAINE / NETWORKING

Briques techniques indépendantes du PORTAL et du Cockpit.

  • API KINGDOMAINE / EPARVIER
  • Services Docker / NGINX
  • Prometheus / Grafana
  • Scripts réseau & métier

Chaque maillon a un rôle clair, aucune confusion entre UI, orchestration et métier.
Principes d’architecture
  • Propre : séparation stricte UI / orchestration / modules.
  • Lisible : pipeline linéaire, étapes nommées, scripts dédiés.
  • Modulaire : modules KING-AO indépendants du PORTAL et du Cockpit.
  • Scalable : ajout de nouveaux modules sans toucher au PORTAL.
  • Professionnelle : logique métier encapsulée, cockpit opérateur clair.
Exemples de commandes (vue opérateur)
  • PORTAL → bouton « Déployer KINGDOMAINE »
  • portal-orchestrator.sh → exporte MODE=deploy, TARGET=KINGDOMAINE
  • STYLE-ORCH-KING-AO.sh → affiche menu de confirmation + options (dry-run, verbose)
  • orchestrator.sh → lit configs, lance docker-compose / scripts associés
  • Modules → API KINGDOMAINE + services réseau, retour d’état au Cockpit
Le Cockpit reste humain, les modules restent techniques — l’orchestrator fait le pont.

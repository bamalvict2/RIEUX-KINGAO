Workflow complet : Dockerfile → Image → Conteneur (multi-projets .NET)

1. Structure du projet

Voici la structure réelle de ton dossier EPARVIER :

EPARVIER/
 ├── docker-compose.yaml
 ├── SolaizeApi/
 │    └── Dockerfile
 ├── SolaizeCockpit/
 │    └── Dockerfile
 ├── Solaize.Shared/
 └── ...

EPARVIER est le dossier racine. C’est le contexte Docker utilisé pour construire toutes les images.

2. Étape 1 : Le Dockerfile construit une image

Chaque projet (API, Cockpit…) possède son propre Dockerfile. Ce fichier décrit comment construire l’image.

Exemple (SolaizeApi/Dockerfile) :

COPY SolaizeApi/SolaizeApi.csproj SolaizeApi/
COPY Solaize.Shared/Solaize.Shared.csproj Solaize.Shared/
RUN dotnet restore
COPY . .
RUN dotnet publish -c Release -o /app

Le Dockerfile utilise des chemins relatifs au contexte (EPARVIER), pas à son dossier.

3. Étape 2 : docker-compose orchestre les images

Le fichier docker-compose.yaml dit à Docker :

  • quel Dockerfile utiliser
  • où il se trouve
  • comment nommer l’image
  • comment lancer le conteneur

Exemple :

services:
  api:
    build:
      context: .
      dockerfile: SolaizeApi/Dockerfile
    image: solaizeapi
    ports:
      - "5000:80"

context: . = Docker voit tout EPARVIER dockerfile: = chemin du Dockerfile image: = nom final de l’image

4. Étape 3 : Construction des images

Depuis le dossier EPARVIER :

docker compose build

Docker fait alors :

  1. Lit le docker-compose
  2. Va chercher chaque Dockerfile
  3. Construit chaque image (API, Cockpit…)
  4. Les stocke localement

Résultat visible avec :

docker images

5. Étape 4 : Création des conteneurs

Une fois les images construites, Docker peut créer les conteneurs. 

docker compose up

Docker fait alors :

  1. Prend l’image solaizeapi
  2. Crée un conteneur basé dessus
  3. Ouvre les ports définis
  4. Fait pareil pour Cockpit, Mongo, Grafana…

Les conteneurs apparaissent avec :

docker ps

6. Étape 5 : Arrêter les conteneurs

docker compose down

7. Résumé visuel du workflow

Dockerfile  →  Image  →  Conteneur  →  Application qui tourne
   ↑            ↑           ↑
   |            |           |
   |            |           └── docker compose up
   |            └── docker compose build
   └── décrit comment construire l’image

Résumé de l'architecture de supervision

1. EPARVIER – Stack applicatif

  • MongoDB : base de données principale
  • Mongo Express : interface d’administration Mongo
  • API .NET (Solaize API) : logique métier
  • Blazor : interface utilisateur
  • Promtail : collecte les logs des conteneurs
  • Loki : stockage et recherche des logs

2. KINGDOMAINE – Stack monitoring

  • Prometheus : collecte les métriques (machine, Docker, Mongo, services)
  • Grafana : tableaux de bord uniques pour toute la supervision
  • Node Exporter : métriques système (CPU, RAM, disque…)
  • cAdvisor : métriques Docker (conteneurs, images, ressources)
  • MongoDB Exporter : métriques de MongoDB
  • Blackbox Exporter : tests HTTP/ICMP (disponibilité des endpoints)

3. Rôle de Grafana et Prometheus

  • Grafana est commun à EPARVIER et KINGDOMAINE :
    • Affiche les métriques venant de Prometheus
    • Affiche les logs venant de Loki
    • Devient le point d’entrée unique de la supervision
  • Prometheus est aussi commun :
    • Scrape les exporters de KINGDOMAINE (node, cadvisor, blackbox, MongoDB)
    • Peut aussi scraper les services d’EPARVIER (API, healthchecks, etc.)

4. Flux simplifiés

  • EPARVIER → Promtail → Loki → Grafana (logs)
  • EPARVIER + KINGDOMAINE → Prometheus → Grafana (métriques)

5. Idée clé

EPARVIER = l’application, KINGDOMAINE = la supervision.
Grafana et Prometheus sont partagés et servent de centre de contrôle unique pour tout ce qui se passe sur la machine et dans les conteneurs.

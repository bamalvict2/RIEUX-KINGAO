1. Structure du projet

Voici la structure reelle de ton dossier EPARVIER :

EPARVIER/
 ├── docker-compose.yaml
 ├── SolaizeApi/
 │    └── Dockerfile
 ├── SolaizeCockpit/
 │    └── Dockerfile
 ├── Solaize.Shared/
 └── ...

EPARVIER est le dossier racine. C'est le contexte Docker utilise pour construire toutes les images.

2. Etape 1 : Le Dockerfile construit une image

Chaque projet (API, Cockpit…) possede son propre Dockerfile. Ce fichier decrit comment construire l'image.

Exemple (SolaizeApi/Dockerfile) :

COPY SolaizeApi/SolaizeApi.csproj SolaizeApi/
COPY Solaize.Shared/Solaize.Shared.csproj Solaize.Shared/
RUN dotnet restore
COPY . .
RUN dotnet publish -c Release -o /app

Le Dockerfile utilise des chemins relatifs au contexte (EPARVIER), pas a son dossier.

3. Etape 2 : docker-compose orchestre les images

Le fichier docker-compose.yaml dit a Docker :

  • quel Dockerfile utiliser
  • ou il se trouve
  • comment nommer l'image
  • comment lancer le conteneur

Exemple :

services:
  api:
    build:
      context: .
      dockerfile: SolaizeApi/Dockerfile
    image: solaizeapi
    ports:
      - "5000:80"

context: . = Docker voit tout EPARVIER dockerfile: = chemin du Dockerfile image: = nom final de l'image

4. Etape 3 : Construction des images

Depuis le dossier EPARVIER :

docker compose build

Docker fait alors :

  1. Lit le docker-compose
  2. Va chercher chaque Dockerfile
  3. Construit chaque image (API, Cockpit…)
  4. Les stocke localement

Resultat visible avec :

docker images

5. Etape 4 : Creation des conteneurs

Une fois les images construites, Docker peut creer les conteneurs. 

docker compose up

Docker fait alors :

  1. Prend l'image solaizeapi
  2. Cree un conteneur base dessus
  3. Ouvre les ports definis
  4. Fait pareil pour Cockpit, Mongo, Grafana…

Les conteneurs apparaissent avec :

docker ps

6. Etape 5 : Arreter les conteneurs

docker compose down

7. Resume visuel du workflow

Dockerfile  →  Image  →  Conteneur  →  Application qui tourne
   ↑            ↑           ↑
   |            |           |
   |            |           └── docker compose up
   |            └── docker compose build
   └── decrit comment construire l'image

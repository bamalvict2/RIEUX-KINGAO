KINGDOMAINE – Feuille de route profonde

Vision, couches, supervision, réplicats et flux opérationnels pour le domaine EPARVIER.

1. Vision d’ensemble

Domaine personnel stable, supervisé, réplicable, avec front métier (C#/Razor/Blazor) et front Ops (Grafana), exposés via Cloudflare/DuckDNS, utilisables aussi depuis Android.

  • Cœur métier : services C# (.NET), Razor/Blazor, logique EPARVIER.
  • Exposition : Cloudflare Tunnel + DuckDNS (fallback / tests).
  • Supervision : Prometheus + Grafana + exporters (app, système, blackbox).
  • Réplicats : Android / Prod stable / Dev.
  • Sauvegardes : Git remote Travail + T3 (FUSE) + archives tar.gz.

2. Couches de l’architecture

2.1 Infra & OS

  • Windows 11 (T3/T7), VMware, disques externes T3/T7/T8/T9.
  • VM Ubuntu KINGDOMAINE (C#, Docker, Prometheus, Grafana).
  • Partages FUSE .host:/UBUNTUSAVEW11 → /mnt/UBUNTUSAVEW11.
  • Objectif : infra reproductible, montée/descente sans douleur.

2.2 Applicatif C# / Razor / Blazor

  • Services C# exposant API + Razor/Blazor pour le front web.
  • Ports clairs (ex : 5000/5001 interne, reverse proxy éventuel).
  • Logs structurés (JSON) pour corrélation avec Prometheus/Grafana.

2.3 Réseau & DNS (Cloudflare / DuckDNS)

  • Cloudflare Tunnel : entrée principale.
  • DuckDNS : entrée alternative / secours.
  • Petit script .sh pour tester Cloudflare KO / DuckDNS OK.
  • À terme : probes blackbox Prometheus.

2.4 Supervision (Prometheus / Grafana)

  • Prometheus : métriques système, app, blackbox.
  • Grafana : front Ops, dashboards par couche.
  • Exporters : node_exporter, blackbox_exporter, métriques .NET.

2.5 Réplicats & Versions

  • Android stable : API figées.
  • Prod stable : version validée.
  • Dev / Lab : terrain de jeu (Razor, Grafana, exporters).

3. Supervision en profondeur

3.1 Stack monitoring

docker-compose.monitoring.yml

  • Prometheus, Grafana, node_exporter, blackbox_exporter.
  • Scrape VM KINGDOMAINE, services C#, probes Cloudflare/DuckDNS.

3.2 Dashboards Grafana

  • Infra : CPU, RAM, disque, uptime.
  • App C# : temps de réponse, erreurs HTTP, requêtes/s.
  • DNS / Tunnel : Cloudflare vs DuckDNS (blackbox).
  • Réplicats / Backups : succès/échecs, taille tar.gz, timestamps.

3.3 Intégration du script de test

  • Option 1 : exposer des métriques via un endpoint texte.
  • Option 2 : utiliser directement blackbox_exporter.
  • Objectif : historique KO/OK visible dans Grafana.

4. Réplicats & Android figé

4.1 Principe

  • Android : API stables, pas de breaking changes.
  • Prod : version validée, quotidienne.
  • Dev : expérimentation.

4.2 URLs / routage

  • https://android.kingdomaine/ → réplicat Android.
  • https://prod.kingdomaine/ → Prod stable.
  • https://lab.kingdomaine/ → Dev.

4.3 Cycle de vie

  • Dev sur réplicat Lab.
  • Supervision via Grafana.
  • Promotion vers Prod si OK.
  • Décision pour Android (changer ou rester figé).

5. Flux opérationnels

5.1 Sauvegardes & FUSE

  • Script universel de sauvegarde EPARVIER → /mnt/UBUNTUSAVEW11/EPARVIER/...
  • Archives BernardBackup-YYYYMMDD-HHMM.tar.gz sur T3.
  • Git remote Travail à jour.
  • FUSE dans les deux sens pour restaurer.

5.2 Routine quotidienne

  • Regarder Grafana en début de session.
  • Travailler sur EPARVIER / C# / Razor.
  • Sauvegarde Git + tar.gz.
  • Vérifier probes Cloudflare/DuckDNS.

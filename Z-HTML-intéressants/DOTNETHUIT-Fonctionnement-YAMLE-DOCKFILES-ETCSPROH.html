Rappel mental : .csproj vs Dockerfile

Mécanisme 1 : .csproj (monde .NET)

.csproj = cerveau du projet .NET

  • Décrit le projet : références, packages, frameworks.
  • Utilisé par dotnet restore et dotnet publish.
  • Dit quels projets partagés (ex: Solaize.Shared) doivent être inclus.
  • Ne connaît rien de Docker, ni des conteneurs.
Mécanisme 2 : Dockerfile (monde Docker)

Dockerfile = chef d’orchestre du build d’image

  • Décide quoi prendre dans le dossier (via COPY).
  • Appelle dotnet restore et dotnet publish sur le bon .csproj.
  • Crée l’image Docker (ex: blazor, solaizeapi).
  • Ne connaît rien du fichier .yml (docker-compose).
À ne pas mélanger :
  • .csproj → monde .NET (code, références, build).
  • Dockerfile → monde Docker (construction d’image).
  • docker-compose.yml → monde orchestration (lance des images, ne lit ni .csproj ni Dockerfile).

👉 Quand tu penses code : .csproj. 👉 Quand tu penses image : Dockerfile. 👉 Quand tu penses conteneurs qui tournent : docker-compose.yml.

Rappel : .csproj ↔ Dockerfile

.csproj ↔ Dockerfile : Comment ils échangent

1. Monde .NET → .csproj

  • Décrit le projet : références, frameworks, dépendances.
  • Utilisé par dotnet restore et dotnet publish.
  • Indique quels projets partagés doivent être inclus.
  • Ne connaît rien de Docker.

2. Monde Docker → Dockerfile

  • Copie les fichiers du dossier (COPY . .).
  • Appelle dotnet restore sur le bon .csproj.
  • Appelle dotnet publish pour compiler.
  • Construit l’image Docker finale.

3. Le pont entre les deux mondes

  • dotnet restore SolaizeCockpit.csproj → lit le .csproj
  • dotnet publish SolaizeCockpit.csproj → compile selon le .csproj
  • Le Dockerfile utilise .NET pour comprendre le .csproj
  • Docker ne comprend pas le .csproj, mais .NET oui.
Intrinsèque SolaizeAPI .NET 8

Ce qu’il faut intrinsèquement pour créer une image SolaizeAPI en .NET 8

  • Le code C# du projet (Program.cs, Controllers, Services, Models, etc.).
  • Le fichier .csproj du projet SolaizeAPI.
  • Les fichiers JSON de configuration (appsettings.json, appsettings.*.json).
  • Le Dockerfile qui copie, restaure, publie et définit l’ENTRYPOINT.
  • L’image SDK .NET 8 pour le build (mcr.microsoft.com/dotnet/sdk:8.0).
  • L’image runtime ASP.NET Core 8 pour l’exécution (mcr.microsoft.com/dotnet/aspnet:8.0).
  • Rien d’autre n’est intrinsèquement nécessaire pour créer l’image.

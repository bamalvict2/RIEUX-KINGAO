Feuille de route KING-AO / DTOS

Objectif : repartir de zéro et obtenir un KING-AO complet, accessible via Tailscale, avec NGINX, Grafana et Razor.

1. Base système & réseau

CORENET
  • Installer Docker + docker-compose sur le NAS.
  • Créer le réseau applicatif :
    docker network create kingao-net
  • Installer et connecter Tailscale sur le NAS (IP privée 100.x.x.x).

2. NGINX front-end KING-AO

CORESEC
  • Installer NGINX sur le NAS (hors Docker ou via Docker dédié).
  • Configurer les locations :
    /grafana, /razor, /orchestrator, /metier, /kingdomaine, /cockpit.
  • Définir les upstreams vers :
    Grafana (3000), Razor (5003), APIs EPARVIER/KINGDOMAINE (8080), cockpit HTML.

3. Monitoring : Prometheus + Grafana

MONITORING
  • Créer un dossier /opt/KING-AO/monitoring avec :
    prometheus.yml, alertmanager.yml, blackbox.yml.
  • Écrire un docker-compose.monitoring.yml pour :
    Prometheus, Blackbox, Alertmanager, Grafana (réseau kingao-net).
  • Ajouter les dashboards et datasources Grafana (Prometheus, Blackbox).

4. Modules métier : EPARVIER & KINGDOMAINE

APPS
  • Créer la structure :
    /opt/KING-AO/modules/EPARVIER et /opt/KING-AO/modules/KINGDOMAINE.
  • Pour chaque module :
    Dockerfile API, Dockerfile Cockpit, docker-compose dédié, scripts build.sh et start.sh.
  • Connecter les services au réseau kingao-net et à NGINX (reverse proxy).

5. Orchestrator & menu shell

CORE
  • Finaliser START-KING-AO.sh (lecture des confs, start/stop/status des modules).
  • Créer un menu shell :
    Build images, Start/Stop modules, Start monitoring, Status global.
  • Option dans le menu pour lancer l’orchestrator :
    bash START-KING-AO.sh start.

6. Razor (maintenance) & intégration NGINX

APPSSEC
  • Créer une petite appli Razor (.NET) :
    pages Start/Stop/Status, Build, Logs, vue modules.
  • La faire tourner sur http://localhost:5003 (Kestrel).
  • Configurer NGINX :
    location /razor { proxy_pass http://localhost:5003; }

7. DTOS via Tailscale

NETSEC
  • Tester l’accès en 4G via l’IP Tailscale :
    http://100.x.x.x/grafana, /razor, /orchestrator.
  • Valider :
    monitoring OK, modules OK, orchestrator OK, NGINX OK.
  • Documenter les URLs et ports dans un petit README KING-AO.
